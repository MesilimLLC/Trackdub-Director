## Leakage enforcement

Each item is built from exactly one refused attempt record (`RecoverySetBuilder.BuildItem`).
The agent's input (`GlimmerPrompt.BuildUserPrompt`) carries only: the source line,
its window and tolerance (and target CPS), the recorded gate failure reasons for
that one failed attempt, the refused candidate of that same attempt, and any
captured scene context (none in this set). It never contains any later revision,
retry, or accepted candidate for the same segment, and never the seeded labels
from `samples/meaning-eval` — the set is built from QA reports (gate outputs),
never from `cases.json` / `pressure-segments.json`.

Known case: voa10-full's "¡Hola!" segment (`voa10f-002`). Its attempt #2 failed
meaning in `qa-report-pass1.json` and qualifies; the passing third revision in
`qa-report-pass2.json` is a sibling attempt and is excluded by construction —
each item is built from a single attempt record, and the prompt builder only
ever receives that item plus this run's own prior recovery attempts. This is
pinned by `RecoverySetBuilderTests.Leakage_rule_excludes_every_other_attempt_text_for_the_same_segment`
and `GlimmerPromptTests.User_prompt_carries_leakage_safe_fields_only`.

## Caps and loop rules

- At most 3 recovery attempts per item; stop at first full pass, cap, or `give_up`.
- Run caps via `CallBudget`: 45 Glimmer calls, 35 hosted Meta calls; a cap hit
  is reported as a cap hit (`RecoveryOutcome.BudgetExhausted`) and no further
  provider call is attempted.
- Per attempt the harness runs `DurationEstimator` timing first; meaning via
  `MeaningGate.CheckMeaningAsync` (template meaning-v1, hosted muse-spark-1.1)
  only if timing passes. Recovered iff timing Pass AND meaning Pass. Glimmer's
  own opinion is never an accept.
- A malformed or off-schema Glimmer reply counts as a failed attempt, is recorded
  as such, and is never repaired silently.
- Route read only from environment: `GLIMMER_BASE_URL`, `GLIMMER_API_KEY`,
  `GLIMMER_MODEL`. Unset route fails closed with zero calls; the key is never
  logged, printed, committed, or stored. Low reasoning (`GLIMMER_REASONING_EFFORT`,
  default `low`).
